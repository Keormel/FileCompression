# Вопросы к защите

1. **Почему выбраны Huffman, LZW и RLE?** Они показывают три разных принципа: статистическое кодирование, словарное сжатие и кодирование серий.
2. **Что общего у алгоритмов?** Все три реализованы самостоятельно и восстанавливают исходные байты без потерь.
3. **Как работает Huffman?** Частоты байтов формируют дерево; более частые символы получают более короткие коды.
4. **Что хранится для Huffman?** Частотная таблица и число значимых битов, необходимые для восстановления дерева и удаления padding.
5. **Как работает LZW?** Повторяющиеся последовательности заменяются кодами словаря, который синхронно строят encoder и decoder.
6. **Как ограничен LZW?** Начальный словарь содержит 256 байтов, код имеет ширину 16 бит, максимум 65535.
7. **Как работает RLE?** Серия одинаковых байтов записывается как `uint32 count` и `byte value`.
8. **Какой алгоритм лучше?** Универсального победителя нет; результат зависит от повторяемости, частот и энтропии конкретного файла.
9. **Почему RLE может увеличить файл?** На данных без серий каждая одиночная запись занимает пять байтов.
10. **Что такое lossless compression?** После распаковки получается точно такой же набор байтов.
11. **Зачем собственный FCMP-контейнер?** Он переносит алгоритм, размеры, имя, metadata, checksum и payload в едином формате.
12. **Зачем SHA-256?** Для обнаружения изменения данных после передачи и распаковки; это не шифрование.
13. **Почему TCP?** Он обеспечивает порядок, доставку и контроль потока для бинарного файла.
14. **Как взаимодействуют пользователи?** Server принимает контейнер User A и помещает его во входящую очередь User B.
15. **Что происходит при повреждении?** FCMP, decoder или SHA-256 выбрасывают доменную ошибку, а GUI показывает понятный статус.
16. **Почему PNG/JPEG/PDF могут плохо сжиматься?** Они часто уже используют внутреннее сжатие, поэтому повторное сжатие не находит избыточности.
17. **Как измеряется ratio?** `original_size / compressed_size`, где compressed включает полный FCMP.
18. **Как измеряется время?** Benchmark использует `time.perf_counter()` отдельно для pack и unpack.
19. **Какие ограничения есть?** Нет TLS/аутентификации, передача ограничена размером фрейма, inbox сервера in-memory.
20. **Почему нельзя просто использовать ZIP?** Цель проекта состоит в сравнении собственных реализаций Huffman, LZW и RLE; готовые compression API скрыли бы исследуемые алгоритмы.
