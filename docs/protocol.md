# TCP-протокол

Каждый фрейм имеет 4-байтную unsigned длину в big-endian и затем payload. Контрольные сообщения являются JSON-фреймами UTF-8; файл передается отдельным бинарным фреймом.

Клиент сначала отправляет `{ "type": "register", "user": "user_a" }`. Затем поддерживаются сообщения `send`, `receive` и `list`. При `send` сервер принимает следующий бинарный фрейм и помещает контейнер в inbox адресата. При `receive` сервер отправляет JSON с размером и следующий бинарный фрейм контейнера.

Сервер поддерживает несколько подключений и минимум двух пользователей. Транспорт рассчитан на учебную сеть: TLS, аутентификация, возобновление передачи и постоянное хранилище являются дальнейшими улучшениями.
